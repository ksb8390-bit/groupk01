# GroupK NAS 재구성 계획서 (초안)

- 작성일: 2026-11-16
- 대상: GroupK, groupk2, groupk3 (QNAP QTS) 3대, 공유폴더 27개
- 성격: 내부 검토용 초안. NAS 모델·용량을 확인한 뒤 '3.1 NAS 역할'을 확정함

---

## 1. 요약 (결론)

| 구분 | 현재 | 목표 |
|---|---|---|
| NAS 역할 | 3대가 같은 업무 자료를 나눠 보관 | **운영 1대 / 보관 1대 / 백업 1대**로 역할 분리 |
| 공유폴더 | 27개 (CM 계열 5개, 설계 계열 5개 분산) | 운영 NAS **8개**, 보관 NAS **3개**로 통합 |
| 폴더 체계 | 공유폴더마다 다름 | **사업부 → 연도 → 프로젝트 → 표준 하위폴더**로 통일 |
| 백업 | 체계 불명확 | 운영 NAS → 백업 NAS **매일 자동 백업**, 월 1회 외장 매체 보관 |
| 정리 | 비정기 | 휴지통 30일 자동 비움, 분기 1회 `cleanup-all` |

**1차 정리 실적 (2026-11-15~16)**

- 중복·백업·풀린 압축 파일 정리: 약 105,500건, 약 1.2 TB
- groupk3 `Network Trashes Folder`(맥 AFP 휴지통) 삭제: 786,310개, 약 1.6 TB
- 합계 약 2.8 TB 확보 예정. 실제 여유공간은 휴지통 비우기와 이전 스냅샷 삭제 후에 반영됨

## 3. 목표 구조

### 3.1 NAS 역할 (권장안, 모델·용량 확인 후 확정)

| 역할 | 배정 기준 | 담는 자료 | 접근 |
|---|---|---|---|
| **운영 NAS** | 가장 최신 모델, 가장 큰 용량, 디스크 상태 양호 | 진행 중이거나 최근 3년 이내 프로젝트, 경영지원, 공용 | 직원 읽기·쓰기 |
| **보관 NAS** | 두 번째 | 준공·종료 후 1년이 지난 프로젝트, 퇴직자 자료, 웹하드·메일 백업 | 읽기 전용 (관리자만 쓰기) |
| **백업 NAS** | 가장 오래되거나 작은 모델 | 운영 NAS 전체의 백업본 (HBS3 매일 증분 백업, 버전 보관) | 직원 접근 불가 |

- 백업 NAS는 가능하면 **다른 층이나 다른 사무실**에 두어 화재·도난에 대비합니다.
- 월 1회 운영 NAS의 핵심 공유폴더를 외장 매체나 클라우드에 추가 백업하면 3-2-1 원칙(사본 3개, 매체 2종, 외부 보관 1개)을 갖추게 됩니다.
- 용량이 운영 NAS에 다 들어가지 않으면 보관 NAS로 넘기는 연도 기준을 앞당깁니다(예: 최근 2년만 운영 NAS).

### 3.3 공유폴더 내부 구조 (사업부 → 연도 → 프로젝트)

```
01_설계/
├── 2026/
│   ├── D2026-001_애월읍_근린생활시설/
│   │   ├── 00_계약·행정
│   │   ├── 01_자료조사/
│   │   ├── 02_계획설계
│   │   ├── …          ← nas_manager.py init 의 업무별 표준 하위폴더
│   │   └── 99_참고
│   └── D2026-002_…
├── 2025/
└── _공통/            ← 사업부 공통 자료 (표준 디테일, 사업부 서식 등)
```

**프로젝트 코드**: `업무구분 + 연도 + 일련번호(3자리)`

| 코드 | 업무 | 공유폴더 |
|---|---|---|
| D | 건축설계 | 01_설계 |
| C | 건설사업관리·감리 | 02_CM |
| U | 정비사업 관리 | 01_설계 또는 별도 (확인 필요) |
| S | 안전진단·점검 | 04_기술연구 (또는 05_안전진단) |
| R | 학술연구용역 | 04_기술연구 |
| I | 인테리어 | 01_설계 |
| P | 제안·입찰·사업개발 | 03_사업개발 |

- 예: `D2026-012_애월읍_근린생활시설`, `C2025-004_제주시_청사증축_CM`
- 코드는 계약 시점에 경영지원에서 부여하고 대장(엑셀)으로 관리합니다.
- 연도는 **계약 연도** 기준입니다. 해를 넘겨도 폴더를 옮기지 않습니다.

### 3.4 파일·폴더 이름 규칙

| 항목 | 규칙 | 예 |
|---|---|---|
| 문서 파일명 | `YYYYMMDD_프로젝트코드_문서명_v01.확장자` | `20261116_D2026-012_설계설명서_v03.hwp` |
| 버전 | `_v01`, `_v02` … 사용. '최종', '최최종', '수정본' 금지 | |
| 폴더 단계 | 프로젝트 폴더 아래 **최대 4단계** | |
| 경로 길이 | 전체 **200자 이내** (맥 1,024바이트, 윈도우 260자 한도 대비) | |
| 금지 문자 | `\ / : * ? " < > |`, 앞뒤 공백 | |
| 받은 자료 | 압축 파일 그대로 `99_참고/YYMMDD_보낸곳_자료명.zip`. 풀어서 쓸 경우 압축 파일은 삭제 | |

## 6. 이관 절차

| 단계 | 작업 | 도구 | 산출물·확인 |
|---|---|---|---|
| 0 | NAS 3대의 모델·용량·디스크 상태 확인 → 역할 확정 | QTS 대시보드, 스토리지 및 스냅샷 | NAS 역할 확정표 |
| 1 | 1차 정리 마무리 (휴지통 비움, AFP 끄기, 스냅샷 정리) | QTS | 여유공간 확인 |
| 2 | 운영 NAS에 새 공유폴더 8개 생성, 사용자 그룹·권한 설정 | QTS 제어판 | 권한표 반영 |
| 3 | 같은 업무 공유폴더끼리 중복 대조 | `nas_manager.py compare --deep` | 병합 대상 목록 |
| 4 | 이관 (공유폴더 하나씩) | 같은 NAS 안: File Station **이동** (즉시)<br>다른 NAS: **HBS3 단방향 동기화**(rsync) | 이관 로그 |
| 5 | 이관 검증: 원본과 사본 대조 (유일본 0건 확인) | `compare` | 검증 결과표 |
| 6 | 원본 공유폴더를 **읽기 전용**으로 전환하고 2주 운영 | QTS 권한 | 직원 문의 대응 |
| 7 | 원본 공유폴더 삭제, 백업 NAS에 HBS3 백업 작업 설정 | QTS, HBS3 | 백업 성공 로그 |

**이관 원칙**

- 공유폴더 하나를 이관할 때는 **금요일 퇴근 후에 시작**하고, 그 공유폴더는 이관 중 쓰기를 막습니다(읽기 전용).
- 맥 Finder로 NAS 사이를 복사하지 않습니다. 느리고, AFP 휴지통 문제가 재발할 수 있습니다.
- 이관 전 경로 과다(498건)는 `lint`로 찾아 이름을 줄이거나 폴더 단계를 줄입니다.

| 보관 이동 | 준공·종료 1년 뒤 프로젝트 폴더를 보관 NAS로 이동 | 사업부 담당 + 관리자 |
| 새 프로젝트 | 코드 부여 → `nas_manager.py init`으로 표준 폴더 생성 | 경영지원 + 사업부 |
| 공용교환 | 30일 지난 파일 자동 정리 | 관리자 |
| 디스크 점검 | 월 1회 SMART 빠른 검사, 분기 1회 RAID 스크러빙 | 관리자 |
| 할당량 | 개인 폴더(homes) 1인 기준 용량 설정 | 관리자 |

## 10. 가정 사항

- NAS 3대 모두 QTS 5.x와 HBS3를 사용할 수 있다고 가정했습니다.
- 직원 PC는 맥과 윈도우가 섞여 있고, 모두 SMB로 접속할 수 있다고 가정했습니다.
- 공유폴더 이름의 '부·본부·팀' 차이는 조직 개편 이력으로 보고, 같은 업무로 판단했습니다(추정).
- 일정은 공유폴더당 이관·검증에 1~2주를 잡은 추정치입니다. 실제 데이터 양과 네트워크 속도에 따라 달라집니다.
